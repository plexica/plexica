## 1. Current semantic API uses and mappings (plan §2.2)

| File                                                                                                                                                                                     | Planned mapping                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/lib/kafka-client.ts`                                                                                                                                                                | `new Kafka({ kafkaJS: {...} })`; validated brokers; Pino bridge; compatibility types                                                                               |
| `src/lib/kafka-producer.ts`                                                                                                                                                              | Producer `kafkaJS` block with explicit acks/retry/auto-create plus outer `linger.ms`; tracked sends and terminal teardown                                          |
| `src/lib/kafka.ts`                                                                                                                                                                       | Await and validate delivery report; managed consumer/rebalance helpers; remove unsupported instrumentation listener; admin                                         |
| `consumer-manager.service.ts`, `dlq-consumer.ts`                                                                                                                                         | Constructor-level offset options; one subscribe; concurrency 1; assignment gate; generation-guarded commit; shared readiness/rebalance rules; disconnect-only stop |
| `lag-metrics.service.ts`, `health-check-kafka.ts`                                                                                                                                        | Shared transient-admin owner; normalized group offsets/high watermarks; bounded `listTopics({timeout})`; always disconnect in `finally`                            |
| `verify-kafka-roundtrip.mjs`, `smoke-redpanda.test.ts`                                                                                                                                   | Replace unavailable `describeCluster`; poll topic metadata/leaders; assignment readiness; no skip; temporary topic; deterministic cleanup                          |
| wrapper consumer paths (`event-pipeline.test.ts`, `ac-06-dlq.spec.ts`) + wrapper `sendKafkaEnvelope` paths (`deletion-event-infrastructure.ts`, `outbox-publisher.ts`, `dlq.service.ts`) | Remove per-subscribe offset and await assignment before events; no call-shape change; inherit acknowledged send and closed-producer behavior                       |
| `event-key-service.ts` + `installation-message-processor.ts`                                                                                                                             | Stable internal failure classes so transient key/DB availability never commits; permanent poison follows acknowledged-DLQ rule                                     |
| plugin lifecycle route/services                                                                                                                                                          | Keep call shapes; make the consumer entry own lag start/stop so every lifecycle path is covered                                                                    |

The current code uses no `assignment()`, `rebalance_cb`, `fetchTopicOffsets()`, or supported consumer `stop()`; the only instrumentation API is `consumer.on('consumer.crash')`, which must be removed rather than emulated.

## 2. Explicit mismatches and resolutions (plan §2)

| Mismatch                                                                                                                            | Resolution in this feature                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Manifest/lock still use patched KafkaJS despite ADR-004/Constitution v1.1                                                           | Replace dependency; remove every patch/lock reference before migration is complete                                                                                                                                       |
| `fromBeginning` passed to `subscribe`; `autoCommit` to `run` (1.10 rejects both)                                                    | Put both in the consumer constructor `kafkaJS` block                                                                                                                                                                     |
| Producer uses defaults; sends not tracked against teardown                                                                          | Explicit acks/retries/backoff/linger; track all owned send promises                                                                                                                                                      |
| No assignment/rebalance state; fixed sleeps; crash listener unsupported                                                             | `rebalance_cb`, assignment generation, bounded readiness helper, sanitized logger, stable failure logs; remove sleeps                                                                                                    |
| CI verifier uses unavailable `describeCluster()`/implicit leader wait                                                               | Poll `fetchTopicMetadata({topics:[temporaryTopic]})`; inspect partition `leaderNode`; never pass `waitForLeaders`                                                                                                        |
| Health timeout can race a second disconnect; setup can leak clients/topic; 200 ms health vs uncancellable native connect/disconnect | Centralize ownership in `finally`; race the public result at 200 ms; keep observed cleanup in a probe-owner registry awaited by shutdown                                                                                 |
| `fetchTopicMetadata()` returns `ITopicMetadata[]`, not `{ topics: [...] }`                                                          | Normalize explicitly; tests assert `partitionId`, `leader`, optional `leaderNode`                                                                                                                                        |
| Verifier treats comma-separated `KAFKA_BROKERS` as one broker                                                                       | Parse all entries; bootstrap array; accept a leader at any endpoint; UUID-suffixed topic for safe cleanup                                                                                                                |
| Key lookup/decrypt poison collapses with transient availability                                                                     | Typed internal key/decrypt outcomes; transient rethrows without DLQ/commit; permanent poison follows sanitized rules                                                                                                     |
| Lag helper sums committed offsets rather than lag; never started                                                                    | Compute `max(0, high - committed)`; start/stop with the consumer lifecycle (minimum KJM-014 fix, not a redesign)                                                                                                         |
| Event worker stop order is not the reverse of startup; real Redpanda smoke conditionally skips                                      | Stop DLQ consumer before outbox publisher, both before producer teardown; remove the skip — unavailable Redpanda is a blocking integration failure                                                                       |
| Architecture/docs carry stale envelope/group/client guidance                                                                        | Update only active guidance; historical ADR/spec/review records remain historical                                                                                                                                        |
| `consumer-manager.service.ts` 193 lines, SDK test 199 lines, `ci.yml` 194 lines, 190-195 line estimates                             | Decompose before adding behavior; native/coverage logic in composite actions with short `uses:` steps; split consumer state/commit and integration fixtures; every authored file <=200 lines, target <=160 for new files |
